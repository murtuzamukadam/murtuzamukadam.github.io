    GPU optimization for LLM inference

    Led from concept to GA · 2024 to 2026

    Teams running LLM inference on Kubernetes were buying GPUs to stay safe on latency. I led the feature that scales inference services on latency and throughput against SLO targets, using Prometheus metrics, so the same hardware carries more traffic.

    In 2025 we made scaling aware of NVIDIA Multi-Instance GPU partitions, so each slice counts as its own unit instead of a whole GPU.

    • Scale your generative AI workloads in Kubernetes (launch blog, 2024)
    • MIG-aware horizontal scaling for LLM workloads (2025)
    • Optimize GPU workloads on Amazon EKS and ROSA (AWS blog, co-author, 2026)
    • Optimizing GPUs for gen AI (IBM case study, 2024)
    • IBM case study: internal LLM platform on 100+ A100 GPUs (2025)

    In-place pod resizing

    Kubernetes 1.33 support · 2025

    Rightsizing used to restart pods, which made teams nervous about automating it. Once Kubernetes allowed it, we changed CPU and memory on running pods, and fell back to the old path only when Kubernetes rules or policies required it.

    • From restarts to real time: in-place pod resizing

    One-click agent updates

    Operations at scale · 2025

    Customers updated the cluster agents by hand, one cluster at a time. Now they select targets in the UI, or run a script on a schedule, and every selected cluster updates in parallel.

    • Introducing one-click updates for Kubeturbo and Prometurbo
